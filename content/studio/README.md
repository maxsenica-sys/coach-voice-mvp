# Content studio

Turns rows of `content/CONTENT_QUEUE.csv` into finished Instagram posts: carousels,
stills and reels, in Pindar's palette, with the same three characters every time.
Nothing is drawn by hand or generated by an image model.

```bash
npm run content:render -- P001 P042    # named posts
npm run content:render -- --day 3      # the three posts the plan puts on day 3
npm run content:render -- --all        # every post in the queue
npm run content:poses                  # every character pose on one sheet, for review
```

Output goes to `content/studio/out/`, which is git-ignored. Each post becomes one
folder, for example `day17_P042_reel_understanding-reply/`:

| File | For |
|---|---|
| `slide-1.png` … `slide-6.png` | carousel, 1080 × 1350 |
| `still.png` | single still, 1080 × 1350 |
| `reel.mp4`, `cover.jpg` | reel, 1080 × 1920, 30 fps |
| `caption.txt` | caption and hashtags |
| `script.txt` | the voiceover to record |

That folder is the handover from the brief: whatever posts reads it as it is.

**Voiceover.** A reel is silent until its voice exists. Record `script.txt`, save
it in the post's folder as `voiceover.m4a`, and render the post again.

Needs Chromium through the repo's Playwright and `ffmpeg` on the path for reels.
A carousel renders in seconds and a reel in under a minute.

## How it is built

- **`cast.js`: the characters.** One rigged skeleton, three costumes (the coach,
  athlete A, athlete B). A pose is about ten joint angles, so faces and proportions
  cannot drift between posts, and moving between two poses is the animation.
  The 24 poses are the brief's pose library, by the same names the queue uses.
- **`studio.js`: the five templates and the phone screens.** Hook, problem,
  mechanic, outcome and call to action, in four colours and one typeface at two
  sizes. A queue row's `ui_card` picks one of six screens, and the feature picks
  what that screen shows, so a wellness post never shows the coverage list.
- **The reel** runs the five beats as five scenes and ends on the wreath. Every
  frame is a pure function of the row and the time.

**The pose columns** map to the slides that carry a character, in queue order:
`pose_1` title card (hook), `pose_2` old way, `pose_3` cost, `pose_4` mechanic
(holding the phone), `pose_5` change. The call to action is the logo frame.

**Truth.** A screen shows only what the app does for that feature. If a feature
changes, change its screen here in the same PR, as you would its copy.

The wreath is read from `lib/brand-mark.ts` and the type from `app/fonts/`, so a
brand change reaches every post on the next render.
